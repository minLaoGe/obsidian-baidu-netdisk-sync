# 并发上传验证（2026-10-19）

- 每轮 9 个随机测试文件：16、128、512 KiB 各 3 个，总计约 1.92 MiB。
- 顺序为 1、3、3、1 并发；每轮文件内容不同，避免秒传影响。
- 串行：11.747 / 14.470 秒，均值 13.108 秒。
- 三并发：5.299 / 3.531 秒，均值 4.415 秒。
- 均值比：2.97 倍。
- 36 个文件全部下载回来逐字节校验一致；测速只计算上传，排除校验下载时间。
- 另测 5 MiB + 17 字节文件：2 个有序分片、2.823 秒上传、下载校验一致。
- 测试目录全部清理；未改动用户笔记或同步基线。

原插件对 precreate.return_type=1 的处理错误，跳过了必需的分片上传，真实上传提交报 31500。此错误已修复。

保留：全库同步互斥锁、本地原子写入锁、同一文件提交顺序、串行冲突和删除处理。
新增：每次成功提交后原子保存基线；保存失败则停止派发并等待正在执行的上传结束；上传前重新检查排队期间的本地变化。

检查：TypeScript、89 项可靠性断言、并发/锁隔离测试、上传协议/中断/凭证刷新测试通过。

边界：速度来自独立 API 测试，真实整库速度受文件大小、服务端提交延迟和网络影响。原子性为单文件提交和可恢复本地替换，不是跨设备、跨整库事务。

真实 Obsidian 桌面验证还发现分片请求手动设置 Content-Length 会报 net::ERR_INVALID_ARGUMENT；已移除该受限制请求头，由客户端自动计算长度。

新版真实知识库观察：41.19 秒内同步基线从 62 增至 165 条，新增 103 条成功提交记录（约 2.501 个文件/秒）。此为局部观察，整库同步仍在继续。
